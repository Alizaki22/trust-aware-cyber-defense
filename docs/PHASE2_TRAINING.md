# Phase 2 Training Guide

**Member 2 — AI/ML & Model Development**

This document explains how to run Phase 2 LoRA fine-tuning for the Detection Agent on a suitable GPU machine. Phase 2 is scoped to the Detection Agent only (D-010). Everything else — agents, verification, trust, evaluation pipeline, dataset — is identical to Phase 1 so that the only difference is fine-tuning (D-005).

> [!IMPORTANT]
> **Do not run `trainer.train()` on the development machine.** That machine has CPU-only PyTorch and ~16 GB RAM. The training script enforces this with a CPU guard that exits early with an informative message.

---

## 1. Why a GPU is Required

| Resource | Requirement | Current dev machine |
|---|---|---|
| GPU VRAM | ≥ 16 GB (LoRA) or ≥ 8 GB (QLoRA) | None — CPU only |
| RAM | ~16 GB beyond the GPU (data, optimizer) | ~16 GB total |
| Compute | CUDA-capable NVIDIA GPU | Not available |

The frozen Qwen3-4B base model weights occupy ~8 GB in bfloat16. Adding the LoRA adapter, optimizer states, and activations pushes total memory well above 16 GB. CPU inference of this scale is also prohibitively slow (many days for 9k examples × 3 epochs).

The Phase 1 Ollama GGUF model is **not** used here — Phase 2 fine-tuning requires the full Hugging Face safetensors weights (`Qwen/Qwen3-4B-Instruct-2507`), downloaded on first run (~8 GB).

## 3. Setup on the GPU Machine

```bash
# Clone the repository
git clone <repo-url>
cd trust-aware-cyber-defense
git checkout feature/phase1-complete   # or the Phase 2 feature branch

# Create a virtual environment
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate

# Install Phase 1 dependencies
pip install -r requirements.txt

# Install Phase 2 fine-tuning dependencies

pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
pip install transformers peft trl datasets accelerate bitsandbytes

# Verify CUDA is available
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

> The UNSW-NB15 split files (`data/splits/train.jsonl`, `data/splits/validation.jsonl`) must be present. They are generated by `python -m src.cli prepare-data` (requires the official UNSW-NB15 CSV files in `data/raw/unsw_nb15/`). The splits are committed to the repository — check they exist before training.

## 4. Pre-Training Steps

### 4a. Validate the dataset

```bash
python scripts/phase2/validate_phase2_dataset.py
```

This checks that all three JSONL splits pass the canonical schema validator (`check_training_record`), that there is no cross-split leakage, and prints the class distribution. It exits with code 1 if any check fails.

**Expected output (key lines):**
```

[PASS]  validation: 8525 records, 0 invalid
[PASS]  test: 45782 records, 0 invalid
[PASS]  train & validation: 0 shared model inputs (leakage check)
[PASS]  train & test: 0 shared model inputs (leakage check)
[PASS]  validation & test: 0 shared model inputs (leakage check)

--- Training set class distribution (76621 total examples) ---
  Normal               37207  ################################################## 
  Exploits             17096  ####################### 
  Fuzzers              11533  ############### 
  Reconnaissance        5074  ####### 
  DoS                   2752  #### 
  Analysis               748  # *** MINORITY ***
  Shellcode              744  # *** MINORITY ***
  Backdoor               722  # *** MINORITY ***
  Generic                640  # *** MINORITY ***
  Worms                  105  # *** MINORITY ***
```

### 4b. Create class-capped sampled splits

```bash
python scripts/phase2/prepare_phase2_sample.py
```

This reads `data/splits/train.jsonl` and `data/splits/validation.jsonl`, applies class-capped sampling (max 2,000 per class, min 100 per class, seed 42), and writes:

- `data/phase2/train_sampled.jsonl` (~9,274 examples after capping)
- `data/phase2/validation_sampled.jsonl`
- `data/phase2/sampling_manifest.json` (reproducibility record)

The original splits in `data/splits/` are **not modified**.

**Why class capping?** The raw training set has a 354x imbalance (Normal: 37,207 vs Worms: 105). Without balancing, the model learns to predict Normal for almost everything, collapsing Macro-F1 — the primary Phase 2 metric. Class capping reduces the imbalance while keeping all minority class examples.

To use a different cap:
```bash
python scripts/phase2/prepare_phase2_sample.py --max-per-class 1000
```

## 5. Running Training

### Standard LoRA (requires ~16 GB VRAM)

```bash
python scripts/phase2/train_detection_lora.py
```

### QLoRA / 4-bit (requires ~8 GB VRAM, recommended for T4/RTX 3060)

```bash
python scripts/phase2/train_detection_lora.py --qlora
```

### Dry run (validates config + data, no GPU required, skips trainer.train())

```bash
python scripts/phase2/train_detection_lora.py --dry-run
```

The training script:

1. Checks for a CUDA GPU (exits with an informative error if absent and not in dry-run mode).
2. Loads config from `configs/phase2/detection_lora.json`.
3. Resolves dataset paths (sampled splits if `sampling.enabled=true`).
4. Downloads Qwen3-4B-Instruct-2507 from Hugging Face (~8 GB, cached after first run).
5. Applies the LoRA adapter configuration.
6. Writes `runs/phase2/detection-lora/experiment_config.json` (effective settings, no secrets).
7. Calls `trainer.train()` (skipped in dry-run).
8. Saves the final LoRA adapter to `runs/phase2/detection-lora/adapter_final/`.

**Expected training time** (approximate):
| Hardware | Mode | Epochs | Time |
|---|---|---|---|
| T4 (16 GB) | QLoRA, ~9k examples | 3 | ~2–4 hours |
| A100 (40 GB) | LoRA, ~9k examples | 3 | ~30–60 minutes |
| RTX 3090 (24 GB) | LoRA, ~9k examples | 3 | ~1–2 hours |

## 7. Phase 2 Evaluation

Phase 2 evaluation uses the **same frozen 494-event test subset** as Phase 1 (`data/eval/phase1_eval_subset_ids.json`, 50 per class, Worms 44). The same four metrics are measured so results are directly comparable.

### 7a. Serve the fine-tuned model

The fine-tuned adapter must be served behind an OpenAI-compatible endpoint (the same interface Phase 1 uses). Two options:

**Option A — vLLM (merge adapter first):**
```bash
# Merge the LoRA adapter into the base model weights
python -c "
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer
model = AutoModelForCausalLM.from_pretrained('Qwen/Qwen3-4B-Instruct-2507')
model = PeftModel.from_pretrained(model, 'runs/phase2/detection-lora/adapter_final')
merged = model.merge_and_unload()
merged.save_pretrained('runs/phase2/detection-lora/merged_model')
AutoTokenizer.from_pretrained('Qwen/Qwen3-4B-Instruct-2507').save_pretrained('runs/phase2/detection-lora/merged_model')
"
# Serve with vLLM
vllm serve runs/phase2/detection-lora/merged_model --dtype half --port 8000
```

**Option B — Ollama (GGUF conversion, advanced):**

Convert the merged model to GGUF format using `llama.cpp`, then serve with Ollama. See the llama.cpp documentation for the conversion steps.

### 7b. Run Phase 2 calibration and evaluation

```bash
# Set environment variables to point Phase 1 evaluation at the Phase 2 model
export PHASE=2
export DETECTION_MODEL=runs/phase2/detection-lora/merged_model

# Calibration (192 validation events → trust history file)
python -m src.cli calibrate

# Evaluation (494 test events → runs/phase2-<timestamp>/)
python -m src.cli evaluate
```

This produces:
- `runs/phase2-<timestamp>/metrics.json` — the four Phase 2 metrics
- `runs/phase2-<timestamp>/results.jsonl` — per-event results

## 9. Key Configuration Reference

All Phase 2 training hyperparameters are in [`configs/phase2/detection_lora.json`](file:///C:/Users/Admin/trust-aware-cyber-defense/configs/phase2/detection_lora.json).

| Parameter | Value | Source |
|---|---|---|
| Base model | `Qwen/Qwen3-4B-Instruct-2507` | D-015 |
| LoRA rank (`r`) | 16 | `docs/LLM_FINE_TUNING.md` typical range |
| LoRA alpha | 32 | `docs/LLM_FINE_TUNING.md` |
| Target modules | q, k, v, o projections | Standard for Qwen attention |
| Learning rate | 2e-4 | `docs/LLM_FINE_TUNING.md` |
| Warmup ratio | 0.03 | `docs/LLM_FINE_TUNING.md` |
| Weight decay | 0.001 | `docs/LLM_FINE_TUNING.md` |
| Epochs | 3 | `docs/LLM_FINE_TUNING.md` recommended range |
| Batch size × grad accumulation | 4 × 4 = 16 effective | GPU memory trade-off |
| Max sequence length | 512 tokens | `docs/LLM_FINE_TUNING.md` |
| Seed | 42 | Reproducibility (P1-06) |
| Sampling strategy | class_capped, max 2,000/class | Imbalance mitigation |
